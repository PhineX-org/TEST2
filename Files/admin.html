الإعدادات والأمان

                    


                    

                        
 تنبيه أمني مهم

                        

                            صلاحية المدير (isAdmin) يتم منحها حالياً عبر رمز يُتحقق منه من المتصفح، ثم يقوم المتصفح نفسه بكتابة isAdmin: true — وهذا لا يمكن أن يكون آمناً بمفرده: أي شخص يعرف الرمز (أو حتى بدون معرفته، لو قواعد الأمان تسمح بالكتابة) يمكنه منح نفسه صلاحية المدير مباشرة من console المتصفح. الإصلاح الحقيقي الوحيد هو قواعد Realtime Database — أضف هذا في Firebase Console → Realtime Database → Rules:
                        

                        
"players": {
  "$uid": {
    "isAdmin": {
      ".write": "auth != null && auth.uid === $uid && (root.child('players').child($uid).child('isAdmin').val() === true || newData.val() === false)"
    }
  }
}

                        
هذا يمنع أي مستخدم من منح نفسه isAdmin: true — فقط من كان مديراً بالفعل يمكنه تعديل هذا الحقل (أو إزالته عن نفسه). منح صلاحية مدير جديدة يجب أن يتم يدوياً من Firebase Console.

                        
                    


                    

                        
 قواعد Firebase المطلوبة للأخبار وسجل الإدارة

                        
أضف هذه المسارات داخل rules في Firebase Console حتى تعمل الأخبار والرسائل الشخصية وسجل الإدارة. اللاعبون يقرؤون فقط؛ الكتابة للمديرين.

                        
"news": {
  ".read": "auth != null",
  ".write": "root.child('players').child(auth.uid).child('isAdmin').val() === true"
},
"userNews": {
  "$uid": {
    ".read": "auth != null && auth.uid === $uid",
    ".write": "root.child('players').child(auth.uid).child('isAdmin').val() === true"
  }
},
"adminLogs": {
  ".read": "root.child('players').child(auth.uid).child('isAdmin').val() === true",
  ".write": "root.child('players').child(auth.uid).child('isAdmin').val() === true"
}
